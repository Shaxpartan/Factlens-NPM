# FactLens NPM v6.7.0 Final Execution Constraints

Date: 2026-08-17

This addendum is normative for the FactLens NPM v6.7.0 implementation.

## Version and compatibility

- Release version is exactly `6.7.0`.
- Existing v6.5.0 `verify()` behavior remains source-compatible for ordinary callers unless an API correctness change requires a coordinated documented adjustment.
- Existing millisecond timeout and forward-only/color-aware CLI progress behavior remain supported.
- New runtime diagnostics must be additive rather than forcing verdict/result consumers to parse transport metadata.

## Detailed runtime metadata

Add a typed detailed verification surface (for example `verifyDetailed()`) that returns verification data plus transport/runtime metadata derived from response headers such as `Server-Timing`.

The SDK must distinguish at least:

- client wall-clock total;
- complete Edge/server wall time when provided;
- auth/pre-auth;
- customization/configuration;
- preserved core verification;
- postprocess/finalization;
- estimated outside-edge gateway/network time where derivable.

Do not label the core-only duration as total server time.

## CLI diagnostics

- Default CLI output remains concise and polished.
- `--verbose` may include the timing breakdown.
- Add a dedicated `--trace`/diagnostic presentation only if it is stable and useful; it must not expose secrets, raw API keys, authorization headers, internal provider credentials, or unsafe request bodies.
- Audio/video progress must distinguish upload, server/transcription wait, resume/poll, core verification, and completion using real observable events; do not invent synthetic percentages for unknowable phases.
- All progress remains monotonic/forward-only and color-aware with clean `NO_COLOR` behavior.

## Reliability

- Support `AbortSignal`/cancellation through SDK request paths where practical.
- Automatic retries are allowed only for explicitly read-only operations and only for bounded transient network/502/503/504 failures. Never auto-retry billable Verify submissions or mutations merely because a response was lost.
- Preserve request IDs/idempotency behavior so callers can explicitly recover safely.

## API/platform parity

Update SDK and CLI types/output for any additive API fields introduced by the unified runtime release, including timing diagnostics and request-detail DTO improvements. Keep customization management, verdict colors, multi-claim results, failed claims, and current v6.5.0 features fully supported.

## Release gate

Before v6.7.0 is promoted to `main`, run the supported Node matrix, typecheck, full tests, examples, CLI behavior tests, timing-header parser fixtures, audio polling fixtures, customization fixtures, and `npm pack --dry-run`. Do not publish to npm automatically.
